Pipeline stages

The workflow leads move through, top to bottom. Role checkboxes replace what used to be hardcoded stage names: Default is where new deals start, Qualified pool feeds the call queue, Triggers nurture enrolls the partner on the service's nurture list on entry, and Won/Lost close the deal (sets closed_at) — a stage can't be both. If more than one stage carries the same role, the call queue uses all of them, but a call outcome (won/lost/nurture) acts on the first one in this order. Also configurable via the API — see GET/POST/PATCH/DELETE /api/v1/stages, authenticated with CRM_STAGES_API_KEY (a separate secret from the lead-ingest API key). Saving a row below sends every checkbox's current state, checked or not — leaving one unchecked before Save turns that role off, it isn't a partial update.
